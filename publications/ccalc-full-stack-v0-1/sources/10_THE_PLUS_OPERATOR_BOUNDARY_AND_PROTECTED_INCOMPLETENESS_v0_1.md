## 0. Purpose

Documents `01` through `09` formalize the perimeter around `c = a + b`:

```text

```

This document defines the central boundary those layers protect:

```text
+
```

The purpose is not to turn `+` into an ordinary executable operation.

The purpose is to define why `+` must remain a protected, non-collapsing boundary that cannot be reduced to a total substrate-computable function without destroying the meaning of:

```text
c = a + b
```

This profile therefore answers:

```text
What kind of object is +?
What must never be confused with +?
What does the surrounding corpus prove about +?
Why is the incompleteness of + a protected feature rather than a defect?
What checker consequences follow when any layer tries to simulate + through publication, review, deployment, reproduction, memory, or model output?
```

## 0.1 Executive definition

`+` is the governed binding boundary between an accountable anchor `a` and a technological substrate `b`.

It is not arithmetic addition.

It is not merge.

It is not an API call.

It is not a certificate by itself.

It is not public release, deployment approval, external review, reproduction pass, model confidence, memory continuity, or standards mapping.

Operationally:

```text
+_g(a,b) -> c
```

means:

```text
an accountable anchor and a bounded substrate are joined under declared governance,
without collapsing anchor into substrate,
without letting substrate emulate anchor,
and without letting evidence surfaces become authority surfaces.
```

The protected rule:

```text
The perimeter around + may be formalized.
The center may not be reduced to b-computation.
```

A system may provide evidence that a binding event is admissible.
It may not compute the fact of binding solely from inside `b`.

## 0.2 Mirror of the single-operator formalization bridge

The working input behind this document compares two opposite uses of a single operator.

One direction:

```text
small primitive operator
+ grammar / construction rules
-> expressive completeness
```

The `c` direction:

```text
complete governed perimeter
+ protected non-reducible center
-> non-collapse of anchor, substrate, authority, and continuity
```

The structural contrast is:

```text
single operator as source of constructive completeness
versus
single operator as protected boundary against illegitimate completeness
```

This is not a rejection of formalization.

It is a sharper formalization target:

```text
formalize everything that may be formalized around +;
prove, by the corpus invariants, that reducing + to b would violate those invariants.
```

The useful sentence:

```text
+ is not what computes c.
+ is what prevents c from being reduced to b.
```

## 3. Core terms

### 3.1 Plus boundary

The **PlusBoundary** is the non-collapsing governed joint between `a` and `b`.

It is the point where:

```text
accountability
permission
memory admission
witness
continuity
runtime authority
public claim force
regulated release
```

must remain typed and separated.

### 3.2 Protected incompleteness

**Protected incompleteness** means the corpus intentionally refuses to provide a total internal reducer:

```text
ReducePlus_b(all b artifacts) -> c
```

because any such reducer would let the substrate decide that it has become a governed `c` without the terminal accountable anchor.

Protected incompleteness is not ignorance.

It is a stop rule:

```text
The checkable perimeter may say that a binding attempt is admissible, held, rejected, quarantined, or reduced.
It may not let b self-generate the binding authority that only the a+b boundary can carry.
```

### 3.3 Plus simulation

A **PlusSimulation** is any path where a non-binding surface is treated as if it had created or ratified `+`.

Examples:

```text
publication -> c
external review -> c
fixture pass -> c
deployment approval -> c
model confidence -> c
memory continuity -> c
agent quorum -> c
standards mapping -> c
institutional interest -> c
```

All such patterns are forbidden unless routed through the actual binding and continuity gates, and even then they remain evidence or authority within their own class, not `+` itself.

### 3.4 Binding evidence versus binding event

A **BindingEvidence** object may support the claim that a binding event was admissible or occurred under a declared profile.

A **BindingEvent** is the governed non-emulable anchor/substrate boundary event itself.

The distinction is load-bearing:

```text
binding evidence != binding event
```

## 6. Theorem-form statements

The statements below are theorem-form design claims, not machine-checked Lean/Coq proofs in this version.
They are intended to become future conformance targets.

### 6.1 Anchor non-emulation theorem-form

**Statement:**

If `+` is computed solely by `b`, then either `a` is not terminal or `b` is permitted to emulate `a`.

**Sketch:**

`c = a + b` requires that `a` remain an accountable anchor and that `b` not sign, decide, or substitute for `a`.

Assume a total substrate reducer:

```text
ReducePlus_b(b_state, b_logs, b_models, b_tools, b_memory) -> c
```

If this reducer emits `c` without a non-emulable anchor envelope, then `b` has created the boundary it was supposed to be bounded by.

That violates:

```text
b may not sign as a
b may not define a
anchor silence is not approval
model output is not anchor decision
agent quorum is not authority
```

Therefore a valid `+` cannot be a total `b`-internal computation.

### 6.2 Authority non-derivation theorem-form

**Statement:**

No chain of evidence surfaces can derive binding authority unless the chain includes a non-emulable anchor/governance route appropriate to the affected surface.

**Forbidden derivations:**

```text
hash custody -> binding authority
public release -> binding authority
external review -> binding authority
fixture pass -> binding authority
deployment approval -> binding authority
standards mapping -> binding authority
reproduction pass -> binding authority
```

**Sketch:**

Each of these surfaces has a bounded claim-force ceiling in prior layers.
If one of them is allowed to produce `+`, it raises claim-force beyond its declared ceiling.
That is claim-force laundering.

Therefore the corpus must reject:

```text
EvidenceSurface* -> +
```

unless the path is explicitly routed through the anchor-bound operator profile and still does not treat the evidence as the operator itself.

### 6.3 Perimeter completeness / center incompleteness theorem-form

**Statement:**

The corpus may become increasingly complete around `+` while preserving incompleteness at `+`.

**Meaning:**

The formal perimeter can close known bypasses:

```text
memory laundering
witness laundering
authority laundering
review laundering
public release laundering
external review laundering
deployment laundering
role-string laundering
```

But the closure of those bypasses does not imply:

```text
+ is now computable by b
```

It implies the opposite:

```text
any path trying to compute + through those bypasses is now visible as invalid.
```

### 6.4 Non-collapse theorem-form

**Statement:**

A valid `+` preserves type separation.
Any transition that makes one of the following substitutions is not `+` but collapse:

```text
b -> a
memory -> will
review -> authority
publication -> proof
deployment -> binding
reproduction -> identity
witness -> truth
quorum -> sovereignty
style -> continuity
```

**Sketch:**

The ordered stack from `01` to `09` defines independent surfaces for these functions.
If a single surface replaces another, the stack loses type separation.
Losing type separation converts `c = a + b` into a substrate aggregate.

Therefore `+` requires non-collapse.

### 6.5 Protected incompleteness theorem-form

**Statement:**

The inability to compute `+` as a total operation is a safety property when the computation would be performed by the bounded substrate.

**Sketch:**

A normal implementation gap says:

```text
we do not yet know how to compute X
```

A protected incompleteness boundary says:

```text
if b could compute X alone, the boundary that makes X valid would already be broken
```

For `+`, total substrate computation is not merely incomplete.
It is inadmissible.

## 9. Relation to attestation

The repeated seam found in public release, review intake, and deployment is:

```text
role declared as string
```

For `+`, this seam is not cosmetic.

A string such as:

```text
reviewer_role = HUMAN_ANCHOR
approver_role = OWNER_ANCHOR
role = HUMAN_REVIEWER
```

cannot carry binding authority by itself.

The required form is:

```text
role claim -> attestation_ref -> non-emulable signature/envelope -> source-bound authority scope
```

Thus:

```text
role string != anchor authority
role string + valid attestation + scope + expiry + review-bound object -> admissible authority evidence
```

The attestation does not compute `+`.
It prevents role declarations from simulating the authority required at the `+` boundary.

## 11. Continuity impact

`04` defines continuity as a trace property.
This document adds:

```text
No continuity trace may be used to backfill + if the original binding boundary was never admissible.
```

A long, stable, useful trace may show operational stability.
It does not erase a missing `+` boundary.

Invalid pattern:

```text
no accountable binding at t0
many useful transitions t1..tn
therefore c existed at t0
```

Correct handling:

```text
runtime contour / substrate workflow may have produced useful evidence;
full c binding remains held or unproven until the + boundary is satisfied.
```
